# Security and operations boundary

**Single-owner MVP, not a public multi-tenant SaaS.** The full video history and all project data are accessible to anyone possessing the MCP secret path. Treat this path as a password, not as an authentication alternative suitable for public launch.

- Generate different 64-character hexadecimal secrets with `openssl rand -hex 32`. `.env.example` intentionally contains invalid placeholders; the server refuses them.
- `MCP_ACCESS_PATH` is a bearer capability inside the HTTPS URL. Do not publish it, send it via unencrypted HTTP, use it in analytics, share it in screenshots or store it in git. Rotate both tokens immediately if one leaks. Avoid access logs that record full URLs.
- `STUDIO_TOKEN` enables bearer-authenticated requests on `/mcp`; signed download links use an HMAC of that token and expire after one hour. Never share it with the ChatGPT prompt.
- Use the bundled reverse proxy with HTTPS; the application container is not published directly. Restrict SSH, firewall the host, and back up Docker volumes and `.env` securely.
- Requests are size-limited, rate-limited by peer address, and checked against allowed `Origin`s. Tool parameters, project IDs and dimensions are validated. Rendering has a three-entry queue cap and a process timeout.
- The renderer only accepts validated local JSON storyboards. It does not fetch arbitrary URLs, run shell commands supplied by tools, or evaluate code generated by the user.
- Generated download URLs can be forwarded by their recipients and should be considered publicly accessible until expiry. No per-user audit or revocation exists without rotating the signing token.
- The `/health` endpoint intentionally returns no secrets. Output and project files persist on disk; use an encrypted backup process.
- `No authentication` in ChatGPT should only be chosen for the secret URL on a trusted, single-owner private deployment. Multi-user authorization requires a real OAuth 2.1 identity provider and scoped access-token verification, which this MVP does **not** implement.
- Real Docker Compose deployment and ChatGPT-account integration must be tested on the chosen host. Local unit/integration tests do not prove TLS, firewall, DNS, IdP or ChatGPT permissions.
