# استقرار شخصی روی VPS مستقل

این راهنما به ارائه‌دهنده خاصی وابسته نیست. هدف یک سرور لینوکسی شخصی با Docker، دامنه اختصاصی، HTTPS و ذخیره‌سازی پایدار است. پروژه در حالت تک‌مالک طراحی شده است.

## پیش‌نیازها

- یک سرور Linux x86_64 (Ubuntu 24.04 یا مشابه)، برای شروع **۲ vCPU، حدود ۲ تا ۴ گیگابایت RAM، دست‌کم ۱۰ گیگابایت فضای خالی** برای تصاویر Docker و رندرهای کوتاه. این ارقام توصیه اولیه‌اند و به تعداد/کیفیت ویدیو بستگی دارند.
- Docker Engine و افزونه `docker compose`. روش نصب به‌روز را از [مستندات رسمی Docker](https://docs.docker.com/engine/install/) بگیرید.
- یک دامنه/ساب‌دامنه مانند `video.example.org` و رکورد DNS نوع A (و AAAA در صورت IPv6 واقعی) به IP سرور.
- باز بودن پورت‌های TCP 80 و 443 در فایروال؛ دسترسی SSH فقط برای مدیر. **نیازی به باز کردن پورت 8787 در اینترنت نیست.**

## نصب و راه‌اندازی

ابتدا کد شاخه اختصاصی پروژه را دریافت کنید:

```bash
git clone --single-branch --branch feature/chat-video-studio-20261118 \
  https://github.com/AlirezaRuohi/Animation-Site.git chat-video-studio
cd chat-video-studio
```

پس از تنظیم DNS، متغیرهای لازم را بدون چاپ رموز بسازید:

```bash
sh scripts/bootstrap-env.sh video.example.org
ls -l .env   # باید فقط برای مالک خواندنی باشد
```

این فرمان دو رمز **متفاوت** ۶۴ کاراکتری می‌سازد. اگر `.env` از قبل وجود داشته باشد، آن را بازنویسی نمی‌کند. کلیدها باید در نسخه‌های پشتیبان امن نیز حفظ شوند؛ با تعویض آن‌ها، ارتباط MCP و لینک‌های دانلود قبلی از اعتبار می‌افتند.

```bash
docker compose up -d --build
docker compose ps
curl -fsS https://video.example.org/health
```

پس از آماده شدن DNS و باز بودن 80/443، Caddy گواهی TLS را خودکار صادر و تمدید می‌کند. **برای محیط عملی `https://` لازم است** و `PUBLIC_BASE_URL` باید دقیقاً دامنه واقعی باشد.

## اتصال به ChatGPT

فقط در ترمینال شخصی سرور آدرس MCP محرمانه را ببینید:

```bash
sh scripts/show-endpoint.sh
```

نشانی را در بخش افزودن سرور MCP سفارشی ChatGPT، اگر حساب اجازه این کار را می‌دهد، وارد کنید و برای این نسخه شخصی گزینه `No authentication` را انتخاب کنید. **این آدرس همانند پسورد حساس است**؛ در فایل README، اسکرین‌شات عمومی، فایل لاگ یا Issue در GitHub منتشر نکنید. برای دسترسی عمومی/چندکاربره باید OAuth و مدیریت هویت جداگانه پیاده شود.

## عملیات روزمره

```bash
docker compose ps
docker compose logs --tail=50 studio
docker compose restart studio
# پس از دریافت نسخه جدید کد:
docker compose up -d --build
```

ویدیوهای در حال رندر هنگام توقف سرویس قطع می‌شوند؛ هنگام راه‌اندازی مجدد، وضعیت آن‌ها `failed` و قابل اجرای دوباره می‌شود. پروژه‌های ثبت‌شده و خروجی‌های موفق روی volume پایدار می‌مانند.

## نسخه پشتیبان، جابه‌جایی و ایمنی

از حجم Docker به نام `studio_data` شامل پوشه‌های `/data/projects` و `/data/outputs` پشتیبان بگیرید؛ از `.env` هم در یک مکان **محرمانه و رمزگذاری‌شده** پشتیبان بگیرید. با انتقال این داده‌ها و کلیدها به یک VPS دیگر، لینک‌های مبتنی بر دامنه قدیمی باید از نو ساخته شوند. گواهی‌ها و تنظیمات Caddy در دو volume دیگرند و در صورت نیاز می‌توانند دوباره صادر شوند.

برای نگهداری فضای دیسک، حجم خروجی‌ها حداکثر با `MAX_OUTPUT_MB` محدود می‌شود و ایجاد پروژه بیش از `MAX_PROJECTS` پذیرفته نیست. این نسخه پاکسازی خودکار نسخه‌های قدیمی ندارد؛ قبل از حذف دستی فایل‌ها، نسخه پشتیبان بگیرید. می‌توان در آینده ابزار حذف امن و سیاست نگهداری اضافه کرد.
